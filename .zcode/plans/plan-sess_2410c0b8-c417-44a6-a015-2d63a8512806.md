# План: code cleaning + оптимизация рендера (полный sweep)

Гарантии: бизнес-логика команд и проверок НЕ меняется. Меняется только: (а) частота рендера HUD (согласовано — каждый кадр) и (б) безопасные чистки (мёртвый код, кэширование, константы). Перед удалением «мёртвых» методов/полей перепроверю grep-ом, что реально нет вызывающих. После каждого блока — `./gradlew compileJava`.

## Блок 1. Оптимизация рендера
1. **`GameRendererMixin.onRender`** — убрать `tick &&` из условия, чтобы `RenderEvent` стрелял каждый кадр в мире без экрана → плавный HUD (сейчас ~20 fps). Экранный путь (`ScreenMixin`) уже стреляет каждый кадр.
2. **`NotificationsService.renderNotificationsLocal`** (L99-111) — главное: `tr.wrapLines(...)` сейчас вызывается **каждый кадр для каждого уведомления**, плюс `split("\n")`. Кэшировать `titleLines`/`bodyLines`: пересчитывать только при создании уведомления и при изменении ширины (хранить `lastWrapWidth`). Это убирает дорогой layout-проход из каждого кадра.
3. **`ReportsParserDrawableElement`** (L200) — `Identifier.of("minecraft","textures/gui/clear.png")` создаётся каждый кадр → вынести в `static final CLEAR_ICON`.
4. **`CheckoutsDrawableElement.renderContent`** (L110) — хардкод `1000` вместо переданного `z` (исправление-чистка: элемент игнорирует свой приоритет).

## Блок 2. Горячие пути: regex/аллокации (затрагивает приём чата — самый частый путь)
5. Один общий `static final Pattern COLOR_CODE = Pattern.compile("§[0-9a-zA-Z]")` и `.matcher(s).replaceAll("")` вместо `replaceAll(...)` в **`ChatService`** (L54, L58, L120) и **`MessageModule`** (L35) — сейчас regex компилируется на каждое сообщение в 4 местах.
6. **`MessageModule.onMessageReceive`** (L38/40/44) — строка `split`-ится до 3 раз; свернуть в одно разбиение/`indexOf`.
7. **`GoogleSheetsService`** — `Pattern.compile` в `parseCellReference`/`extractSpreadsheetId`/`extractGid`/`parseCellData` (L157 — per-cell!) → `static final`; `HttpClient` (L66) — переиспользовать один `static final` вместо `newBuilder()` на запрос; поправить копипаст-лейблы в ошибках (L73/L78 говорят "NetService").
8. **`StateModule`** — `address.matches("(?i).*hol(l)?yworld.*")` (L336, на каждый коннект) → `static final Pattern HOLYWORLD_ADDR`.
9. **`NetService`** — убрать `new Gson()` в `getListAsync` (L55, тенит поле L38); `new TypeToken<>(){}.getType()` (L56/57, L421/422) → `static final Type`; поля `journalApiUrl`/`gson` → `static final`; `getResponse` (L410) → `private` (нет внешних вызывающих).
10. **`HolyWorldPatterns`** — `replaceFirst("^по причина:\\s*",...)` (L230) → `static final Pattern`.

## Блок 3. Инфраструктура (EventBus / DI)
11. **`EventBus.register`** (L31-33) — баг: при обнаружении дубля делается `return` (прерывает регистрацию остальных методов того же объекта) → `continue`. Дубликаты отслеживать через `Set<String>` (target+method) вместо O(n²) stream-сканирования всех подписчиков.
12. **`EventBus.getModule`** (L58-65) — мёртвый код (`ModuleManagerService` имеет свой map-based `getModule`); удалить после проверки grep.

## Блок 4. Мёртвый код (удалить после подтверждения grep, что нет вызывающих)
13. `HolyWorldPatterns.banStatusMatcher` (L244-246).
14. `GoogleSheetsService` — неиспользуемые методы `Spreadsheet` (getCell/getRow/getRange/getFlatRange/getRowCount/getColumnCount/isEmpty) — оставить `getColumn`, остальное удалить если реально неиспользуемо.
15. `TwinksCheckModule.loadResults` (L479) — если нет вызывающих.

## Блок 5. Чистка: константы и стиль
16. **`StateModule`** (L103/109/116/123/129) — `setX(isX())` self-assign no-op'ы. Удалю **только после проверки**, что сеттеры — простые field-сеттеры без побочных эффектов (иначе оставлю с комментарием).
17. **`NetModule.RANKS`** (L29-39) — double-brace init → `Map.of(...)` (ровно 9 записей, укладывается).
18. `static final` для детерминированных полей: `ChatService.HMTextComponent`/`Chars` (L26-28), `ConfigManagerService` `HEADER`/`FOOTER` (L83-138 — сейчас non-final locals), `TwinksCheckModule` `workDir`/`checkFile`/`tempFile` (L44-46).
19. Именованные константы для магических чисел: `SettingsModule` MAX_TEXT_LENGTH (L158)/hud-scale границы (L248), `SpyModule` 500ms (L169), `NetService` таймауты 10_000/15_000 (L430), `StateModule` `"minecraft:spawn_world"` (L94/L246), `TwinksCheckModule` 24.0/1440.0/30 (L92).
20. Пустые `catch` (L88/L251 в TwinksCheck) — добавить логирование через `loggerService` (если сервис доступен) или хотя бы комментарий, почему глотается.

## Порядок и проверка
- Блоки 1 → 5 по очереди, `compileJava` после каждого блока.
- Финальный прогон `./gradlew compileJava`.
- Поведение команд/проверок/событий не меняется; меняется только плавность HUD и чище/быстрее код на горячих путях.
