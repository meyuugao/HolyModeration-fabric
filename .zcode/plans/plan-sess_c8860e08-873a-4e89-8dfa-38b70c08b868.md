## Логика X — частичная блокировка мода при устаревшей версии + уведомление

### Суть
Заменить текущую **полную** блокировку при несовпадении версии (в `NetModule.needUpdates`) на **частичную** (Логику X): остаётся базовый функционал для проведения проверок, всё остальное вырубается. При этом показывается понятное уведомление, почему функционал заблокирован.

### Состав модулей в режиме Логики X (после блокировки)
**Остаются активны (перерегистрируются):**
- `StateModule` — обработка/отмена команд (нужен, чтобы блокировать /hm enable|disable, но позволять frz-команды)
- `GuiManagerModule` — рендер HUD (показывает только активные drawable)
- `CheckoutsModule` — frz/автобан/sban/sendtexts/проверки (базовый функционал). Как `DrawableModule` автоматически добавится в рендер HUD → таймер проверки и замороженный игрок видны
- `NotificationsModule` — уведомления (чтобы пользователь видел уведомление о блокировке)

**Вырубаются (не перерегистрируются):**
- `SpyModule` (слежка), `WaterMarkModule` (ватермарка), `MainGuiModule` (меню по правому Shift), `SettingsModule` (настройки), `NetModule` (сетевая синхронизация), `PunishmentsModule`, `MessageModule`, `ReportsParserModule`, `TwinksCheckModule`, `KeyBindingModule`

> Автобан работает: `CheckoutsModule.onMessageReceive` вызывает `punishmentsService.punish(...)` напрямую (сервис из DI), а не через `PunishmentsModule`.

### Изменения по файлам

**1. `ModStateService.java`** (основная логика)
- Добавить зависимость `NotificationsService` (цикла зависимостей нет — `NotificationsService` не зависит от `ModStateService`)
- Новый флаг `private boolean updateBlocked = false;` (геттер `isUpdateBlocked`)
- Метод `blockForUpdate()`: ставит `updateBlocked = true`, `blocked = true`, делает `unregisterAll()`, затем перерегистрирует 4 модуля (State, Gui, Checkouts, Notifications); показывает уведомление WARNING: «Мод переведён в ограниченный режим из-за устаревшей версии. Доступны только проверки (frz, автобан). Обновите мод, чтобы вернуть весь функционал» (длительное время показа)
- Метод `unblockForUpdate()`: ставит `updateBlocked = false`, `blocked = false`, вызывает `registerEventListeners()` (полный набор); показывает уведомление SUCCESS: «Мод обновлён — весь функционал снова доступен»
- Защита в `enable()` и `disable()`: если `updateBlocked == true` → сразу `return false` (команды /hm enable и /hm disable не действуют, как вы выбрали)

**2. `NetModule.java`** (триггер и авто-разблокировка)
- В `needUpdates()`: заменить `modStateService.block()` на `modStateService.blockForUpdate()` (уведомление о блокировке показывается внутри blockForUpdate, плюс остаётся существующее уведомление со ссылкой на новую версию)
- В `refresh()`: после `if (needUpdates()) return;` добавить проверку — если `modStateService.isUpdateBlocked()`, вызвать `modStateService.unblockForUpdate()` (**авто-разблокировка при перезаходе** после обновления мода, когда версия снова совпадёт)

**3. `StateModule.java`** (защита от преждевременной разблокировки)
- В `onServerConnect` (priority 101): условие авто-unblock дополнить проверкой `&& !modStateService.isUpdateBlocked()`, чтобы `StateModule` не снял Логику X раньше, чем `NetModule.refresh` проверит версию

### Поток авто-разблокировки при перезаходе после обновления
1. `StateModule.onServerConnect` (priority 101): `isUpdateBlocked()==true` → НЕ разблокирует
2. `NetModule.onServerConnect` → `refresh()` → `needUpdates()`: версия совпала → вернёт `false` → дошли до `if (isUpdateBlocked()) unblockForUpdate()` → полный набор модулей снова активен + уведомление об успехе
